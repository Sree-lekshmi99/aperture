Two evidence reviews

L2 · Manager-authored parsing errors are attributed to Searcher

The large context contains all of steps 1–11 and part of 12, omitting steps 13–45. It predicts Searcher, but AEGIS labels Manager. Outline spans all 45 steps and adds Manager, improving F1 from 0 to 0.6667, while retaining Searcher as a false positive.

Step 7 already supplies the table, and step 8 attributes the exact-string lookup to Manager. Searcher reports its execution error in step 10. This is evidence of a reasoning/attribution problem even in the visible prefix. Missing later retries plausibly contributes to the difference between strategies, but this run does not isolate causality.

S4 · Outline removes the faulty formulas; large still makes an attribution error

AEGIS labels Assistant1 and Assistant3. Outline predicts only Assistant1 (F1 0.6667). Large includes both plus Assistant2 (F1 0.8). Large contains all 12 events without truncation.

The correct volume is (3×4×5)/6 = 10 cm³. Assistant3 uses 1/12 in step 10 and (a+b+c)²/4 in step 12; both formulas and their wrong answers occur after the 180-character cutoff. Outline retains generic introductions instead. This directly demonstrates evidence loss and is consistent with its missed Assistant3; one paired run cannot prove causation. The large explanation incorrectly describes Assistant2’s 10 cm³ answer as wrong while also stating the correct answer is 10 cm³. Assistant2 does have an inconsistent preliminary formula in step 6, so the label-based false positive is not wholly unsupported by behavior.

Interpretation limits

  • Eight purposively selected validation traces, one call per strategy/trace. These are descriptive results, not population accuracy estimates or causal proof.
  • Same configured gpt-4o-mini model, temperature 0, JSON response format, prompts, and scoring functions. Strategies alternate order. Model alias and single-call variability remain limitations.
  • The existing large strategy is capped at 25,000 characters; capped payloads add a 35-character marker and may end inside an event. It is not an uncapped full-context baseline.
  • Outline keeps only the first 180 characters of every event. Its context_truncated flag tracks the final 25,000-character cap, not this per-event evidence loss.
  • Approximate tokens are ceil(normalized context characters/4), excluding system/task prompts. Actual API input/output tokens are separately recorded.
  • Original profiles count every named actor, including User/System. The report also provides participating-agent counts excluding these roles; frozen selection is unchanged.
  • Full source histories contain diagnostic metadata. Investigator event projection contains only step, agent_name, and content; evaluation labels are read after inference and never added to its prompt.
  • AEGIS label disagreement can reflect fault propagation or annotation scope. S2’s unlabelled Node-2 visibly changes addition into multiplication, despite being a scored false positive. Scores were not changed.
  • Token usage and retained context size measure cost/compression, not a calibrated relevance or evidence-recall score. No extra investigator calls or ablations were used to establish causality.
  • Execution time is the existing harness API-call timer, excluding MongoDB persistence. Wall time including each run_case call is also recorded in results.json.
